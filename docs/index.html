file2video config generator

Build a file2video.conf file for the file2video CLI. Drop it in the directory where you run the program (or pass --config <PATH>) and every value below becomes a default for encode, decode, estimate and benchmark. Command-line flags always override this file. Import an existing file2video.conf below to edit it, or start from scratch. Encode with --no-password to skip encryption, or enter a password when asked; everything here is optional tuning.

Quality & speed

Stealth mode

Defaults for encode --stealth <background.mp4>, which hides the file as a faint luma layer over a background video you provide. Decoding is blind, so none of these matter on decode.

stealth_dense — double the stealth data rate: sixteen modulation levels (four bits per block pair) instead of four; pair with intensity 40+ for aggressive platforms such as YouTube

Hardware

Encryption. Video files are encrypted with a password (AES-GCM + PBKDF2) unless you encode with --no-password; the videos travel through YouTube and other platforms and should stay private. There is deliberately no password = value in this file, so passwords never end up on disk by accident. Tuning the work factor with pbkdf2_iterations is the supported way to make encoding cheaper or stronger.

file2video.conf

Save this as file2video.conf next to file2video.exe / in your working directory, or pass it explicitly with --config file2video.conf. The encoder also keeps its benchmark results in file2video-calibration.conf; with optimise set, it reuses them automatically and re-calibrates whenever your hardware changes.

Estimated result

Lengths, frames, durations and the Reed-Solomon bookkeeping are computed exactly like the Rust encoder does it. The MP4 file size is a measurement-based estimate, not a promise: hardware encoders differ; budget ±25%.
